IoT KTP Access API v1.0

Base URL: https://iot.airashi.biz.id/api/v1

Authentication

JWT-based authentication. Access tokens expire in 15 minutes. Use refresh tokens to get new pairs.

POST/auth/registerRegister new user
PUBLIC First user auto-becomes admin. After that, ADMIN required via POST /auth/users.

Registers a new user in the system. The very first user registered will automatically be assigned the "admin" role. Subsequent registrations might require admin privileges depending on configuration.

Request Body
{
  "name": "Admin User",
  "email": "admin@example.com",
  "password": "securepassword",
  "role": "admin"          // optional: "admin" | "operator"
}
Response 201
{
  "success": true,
  "message": "User registered successfully",
  "data": {
    "id": "uuid",
    "name": "Admin User",
    "email": "admin@example.com",
    "role": "admin"
  }
}
POST/auth/loginLogin & get tokens
PUBLIC

Authenticates a user and returns an access token (valid for 15 minutes) and a refresh token (valid for 7 days). Use the access token in the Authorization header for subsequent API calls.

Request Body
{
  "email": "admin@example.com",
  "password": "securepassword"
}
Response 200
{
  "success": true,
  "data": {
    "user": { "id": "uuid", "name": "Admin", "email": "admin@example.com", "role": "admin" },
    "tokens": {
      "access_token": "eyJhbGci...",
      "refresh_token": "eyJhbGci...",
      "token_type": "Bearer",
      "expires_in": 900
    }
  }
}
POST/auth/refreshRefresh access token
PUBLIC

Generates a new access token using a valid refresh token. This allows users to stay logged in without needing to re-enter their credentials every 15 minutes.

Request Body
{ "refresh_token": "eyJhbGci..." }
Response 200
{
  "data": {
    "access_token": "new_token...",
    "refresh_token": "new_refresh...",
    "token_type": "Bearer",
    "expires_in": 900
  }
}
GET/auth/meGet current user profile
JWT Header: Authorization: Bearer <access_token>

Retrieves the profile information of the currently authenticated user based on the provided access token.

Response 200
{
  "data": {
    "id": "uuid", "name": "Admin", "email": "admin@example.com",
    "role": "admin", "is_active": true, "created_at": "2026-05-01T10:00:00Z"
  }
}
POST/auth/logoutLogout (discard tokens)
JWT

Logs out the current user. Since this is a stateless JWT implementation, the client should discard the tokens locally after this call.

Response 200
{ "message": "Logged out successfully. Please discard your tokens." }

IoT Devices

Device modes: pending active register inactive

POST/devices/provisionProvision a new device
PUBLIC Requires provision_key if PROVISION_SECRET is set in .env

Registers a new physical IoT device to the system. Returns a unique node_id and api_key that the device must save and use for future authentication. The device starts in a "pending" mode until an admin activates it.

Request Body
{
  "hardware_id": "ESP32-A1B2C3",
  "device_name": "Main Entrance Scanner",
  "provision_key": "your_provision_secret"
}
Response 201
{
  "data": {
    "node_id": "node-xxxx-xxxx",
    "api_key": "generated_api_key",
    "device_name": "Main Entrance Scanner",
    "mode": "pending",
    "message": "Device provisioned. Waiting for admin activation."
  }
}
GET/devices/me/statusDevice checks own status
DEVICE Headers: X-API-Key + X-Node-ID

Used by the IoT device as a heartbeat (ping). Returns the device's current mode ("active", "register", etc.) so the device knows how to behave. Calling this endpoint automatically updates the device's "last seen" uptime in the database.

Response 200
{
  "data": {
    "node_id": "node-xxxx", "device_name": "Main Scanner",
    "mode": "active", "location": "Lobby", "last_seen_at": "..."
  }
}
GET/devicesList all devices
JWT

Retrieves a list of all IoT devices registered in the system. Used to populate the devices dashboard.

Response 200
{ "data": { "devices": [...], "total": 3 } }
GET/devices/:node_idGet device detail
JWT

Retrieves detailed information about a specific IoT device by its Node ID.

Response 200
{ "data": { "id": "...", "node_id": "...", "device_name": "...", "mode": "active", ... } }
PUT/devices/:node_idUpdate device name/location
JWT

Updates the basic information (name and physical location) of an IoT device. Mode changes are handled via a separate endpoint.

Request Body
{ "device_name": "New Name", "location": "Floor 2" }
PUT/devices/:node_id/modeSet device mode
ADMIN + JWT

Changes the operating mode of the device (e.g., from "active" to "register" to allow new KTP scanning). Requires administrative privileges.

Request Body
{ "mode": "active", "location": "Lobby" }
// mode: "active" | "register" | "inactive" | "pending"
DEL/devices/:node_idDelete device
ADMIN + JWT

Permanently deletes a device from the system. Requires administrative privileges.

Members

GET/membersList members (paginated)
JWT

Retrieves a paginated list of all registered members (people with KTP access). Supports searching by name or NIK.

Query Params
ParamTypeDescription
pageintPage number (default: 1)
limitintItems per page (default: 20, max: 100)
searchstringSearch by NIK or name
Response 200
{
  "data": {
    "members": [...],
    "pagination": { "total": 50, "page": 1, "limit": 20, "pages": 3 }
  }
}
POST/membersRegister new member
JWT

Registers a new member manually via the dashboard. The NIK must be exactly 16 digits.

Request Body
{
  "nik": "1234567890123456",   // required, 16 digits
  "name": "Budi Santoso",      // required, min 2 chars
  "address": "Jl. Merdeka 1",
  "birth_date": "1990-01-01",  // YYYY-MM-DD
  "phone": "081234567890",
  "photo_url": "https://..."
}
GET/members/:idGet member by ID
JWT

Retrieves detailed information about a specific member using their unique database ID.

GET/members/nik/:nikGet member by NIK
JWT

Retrieves detailed information about a specific member using their 16-digit NIK.

PUT/members/:idUpdate member
JWT

Updates member details. Note that the NIK cannot be changed after registration. The "is_active" flag can be toggled to grant or revoke access.

Request Body
{
  "name": "New Name",
  "address": "New Address",
  "phone": "08xxx",
  "birth_date": "1990-01-01",
  "is_active": true
}
DEL/members/:idDelete member
ADMIN + JWT

Permanently deletes a member and their access rights from the system. Requires administrative privileges.

KTP Tapping

Device taps KTP cards. In active mode: grants/denies access. In register mode: registers new members.

POST/ktp/tapProcess KTP tap from device
DEVICE Headers: X-API-Key + X-Node-ID
Request Body
{
  "nik": "1234567890123456",
  "name": "Optional Name"       // used in register mode
}
Response (Active Mode - Granted)
{ "data": { "action": "granted", "message": "Access granted", "member": {...}, "device_mode": "active" } }
Response (Active Mode - Denied)
{ "data": { "action": "denied", "message": "Access denied: NIK not registered", "device_mode": "active" } }
Response (Register Mode - New)
{ "data": { "action": "registered", "message": "KTP registered as new member", "member": {...}, "device_mode": "register" } }
GET/ktp/logsGet all access logs
JWT
Query Params

Authentication Guide

This API uses 3 authentication methods:

MethodHeaderUsed By
JWT BearerAuthorization: Bearer <token>Admin dashboard, operators
Device AuthX-API-Key + X-Node-IDIoT hardware devices
Admin OnlyJWT with role=adminDelete, set mode, create users

1. Login & Get Token

curl -X POST https://iot.airashi.biz.id/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"yourpassword"}'
const res = await fetch('https://iot.airashi.biz.id/api/v1/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    email: 'admin@example.com',
    password: 'yourpassword'
  })
});
const { data } = await res.json();
const token = data.tokens.access_token;
console.log('Token:', token);
import requests

res = requests.post('https://iot.airashi.biz.id/api/v1/auth/login', json={
    'email': 'admin@example.com',
    'password': 'yourpassword'
})
token = res.json()['data']['tokens']['access_token']
print('Token:', token)
package main

import (
    "bytes"
    "encoding/json"
    "fmt"
    "net/http"
)

func main() {
    body, _ := json.Marshal(map[string]string{
        "email": "admin@example.com",
        "password": "yourpassword",
    })
    resp, _ := http.Post("https://iot.airashi.biz.id/api/v1/auth/login",
        "application/json", bytes.NewBuffer(body))
    defer resp.Body.Close()
    var result map[string]interface{}
    json.NewDecoder(resp.Body).Decode(&result)
    fmt.Println(result)
}

  int code = http.GET();
  if (code == 200) {
    String response = http.getString();
    DynamicJsonDocument doc(1024);
    deserializeJson(doc, response);
    
    // Server updates last_seen_at automatically.
    // Read current mode to decide what to do
    String currentMode = doc["data"]["mode"]; 
    if (currentMode == "active") {
       // Normal operation
    } else if (currentMode == "register") {
       // Wait for new cards to register
    }
  }
  http.end();
}

# Filter by device

  -H "Authorization: Bearer YOUR_TOKEN"

# Filter by NIK

  -H "Authorization: Bearer YOUR_TOKEN"

# With pagination
curl "https://iot.airashi.biz.id/api/v1/ktp/logs?page=1&limit=50" \
  -H "Authorization: Bearer YOUR_TOKEN"
